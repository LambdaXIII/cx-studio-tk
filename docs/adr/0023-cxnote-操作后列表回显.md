# cxnote 操作后列表回显：所有动词成功后确认行 + 当前域直属条目

> 领域：cxalio-studio-tools（cxnote）· 适用范围：cxalio-studio-tools · cxnote

## 决策

cxnote 全部动词（`add` / `finish` / `pend` / `reset` / `erase` / `clear`）在人读模式下**操作成功后，确认行照旧，其下追加打印当前工作域的直属条目列表**：

- **回显范围仅当前域直属条目**：不含下级域条目，也**不显示下级域标题行**——与 `list` 默认折叠视图（下级域以标题行成目录）不同，操作后回显是「只看现场」的视图，不承担浏览下级域的职责。
- **条目含全部状态**：待办 / 进行中 / 已完成（带状态标号与 dim 样式），行样式与 `list` 条目行一致（ADR-0020 的每域小表，单域块形态）。
- **重复 `add` 同样回显**：幂等回执既有条目后照常打印确认行与列表——新建与回执两个分支行为对称。
- **空态**：回显时当前域无直属条目（`clear` 后常见），打印「当前域暂无条目」（与 `list` 空态文案一致），不静默。
- **`--json` 契约不变**：所有动词的 JSON 输出维持既有对象形态（`add` 条目对象、`clear` 被清空条目数组、其余更新后的条目对象），不附加列表数据。回显是人读体验，不进入机器契约。
- **失败路径不回显**：SafeError 中止（缺内容、无命中、多义命中、clear 未确认）时维持纯错误输出，不打印列表。

## 理由

- 操作的目的是改动状态，改动之后立刻看到「现在域里有什么」闭环了反馈环——省去再敲一次 `list`；确认行回答「刚才那条操作落到哪」，列表回答「现场现在长什么样」，两者职责不同、共存互补。
- 统一为**全部动词**而非仅 `add`：状态流转（finish/pend/reset）与删除（erase）同样是状态改动，操作后现场一并可见；按动词区别对待会造出记忆负担与不一致的输出形态。
- 范围收窄为**当前域直属条目**：操作现场是当前域；下级域内容在操作场景是噪声，标题行也不需要——想浏览下级域用 `list`。
- JSON 契约不动：help 文档已向脚本消费方承诺幂等条目对象；回显是终端人读体验，混入 JSON 会让同一命令出现两种输出语义（违背 ADR-0020 确立的「机器契约与人读可见范围一致」原则的另一半——机器契约保持稳定）。

## Considered Options

- **仅 `add` 回显**（原始提案）：用户否决——所有操作都改状态，统一回显。
- **回显默认 `list` 视图**（含下级域折叠标题行）：被否——下级域标题行在操作场景是噪声，回显只看当前域现场。
- **回显 `--full` 视图**（下级域全展开）：被否——同上且更冗长。
- **列表取代确认行**：被否——确认行是操作回执（重复 add 回执既有条目时尤其必要），列表是现场快照。
- **`erase` / `clear` 不回显**（中期共识）：被推翻——删除也是状态改动，统一为全部动词回显；`clear` 后空态文案自然呈现结果。
- **JSON 输出附加列表**：被否——脚本消费方契约（help.md 承诺的对象形态）不变。

## Consequences

- 人读输出从单行确认变为「确认行 + 列表」，输出变长——换取操作后状态立即可见，已确认接受。
- `finish` / `pend` / `reset` 的文本匹配范围是可见域（当前域 + 下级域）、ID 匹配是全库：目标命中下级域条目时，确认行照常给出 `[id]`，但其后回显列表不含该条目——统一视图的接受代价。
- 复用 ADR-0020 的单域块渲染，不新增渲染形态；无框三列小表、徽章样式均不变。
- 帮助文档（help.md / help.en_US.md / README）与 i18n 文案需同步描述此行为，实现时一并落地。
