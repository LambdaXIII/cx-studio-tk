# cxnote 目标动词重复参数去重

> 领域：cxalio-studio-tools（cxnote）· 适用范围：cxalio-studio-tools · cxnote

实现 ADR-0024 的批量参数时暴露一处其未覆盖的边界：目标动词（`erase` / `finish` / `pend` / `reset` / `drop`）的参数列表里出现同一目标两次（`finish abc abc`）时该怎么解释。本条记录实现期的定案。

## 决策

- **重复目标按条目去重，保留首次出现**：目标解析阶段以条目 ID 去重——同一目标无论以 ID、文本片段还是两者混写出现多次，只保留首次出现的解析结果。确认行的「N 条」与 `--json` 数组长度都等于去重后的目标数，两者始终与实际处理的条目一一对应。
- **只对目标参数去重，add 不去重**：`add` 的参数是内容而非目标，参数个数即待录入的内容个数，`add 牛奶 牛奶` 仍回执「已记录 1 条 + 已存在 1 条」（ADR-0024 已定）。

## 理由

「N 条」是确认行与 JSON 数组共同的事实陈述，必须等于实际处理数。若重复目标被重复处理，第二次 `erase` 会因条目已删而没有结果可比，数组无法保持「一参数一元素」，确认行也会声称处理了并不存在的两条；若改为报错，则对 `finish x x` 这类无害重复过于严苛——重复目标不是输入错误，只是冗余。去重对用户是「同一件事说了两遍」的自然语义：命令成功、结果唯一、计数诚实。

## Considered Options

- 按参数重复应用（`finish abc abc` 转移两次、`erase abc abc` 第二次无结果）：被否——破坏「N 条 = 实际处理数」，JSON 数组与确认行无法一一对应。
- 重复目标视为解析错误、整体中止：被否——把冗余当错误，对无害输入过严，且需新增一类错误汇报形态。
- 在参数层去重（字符串相同即合并）：被否——同一目标的 ID 写法与文本写法不同（`abc` 与「买菜」），必须在解析为条目之后去重才完整。

## Consequences

- 目标解析结果天然唯一，`NoteStore.transition` / `NoteStore.erase` 的返回值不再有 None 分支，实现以 `assert` 表达该不变量。
- 确认行与 JSON 数组的长度语义固定为「去重后的目标数」；帮助文档按此口径描述。
- `add` 不受影响：其参数是内容，重复内容照旧走「已记录 + 已存在」双行回执。
