# cxnote 不定项批量参数与 drop 取消状态

> 领域：cxalio-studio-tools（cxnote）· 适用范围：cxalio-studio-tools · cxnote

v1.1.1 后用户提出两项改进：条目级动词支持不定项参数便于批量处理；新增第四状态——内容不再适用但保留在库、可被 reset 拉回。状态定名「已取消」（用户拍板），动词 `drop`。经设计盘问（两轮 + 清理语义纠正一轮）逐项定案如下。

## 决策

- **不定项批量参数化全部条目级动词**：`add`、`erase`、`finish`、`pend`、`reset`、`drop` 的参数从单个扩为多个，每参数一条（add 每参数一条内容，`\n` 转换逐参数进行）；`clear` 是域级动作、无目标参数，不参与。单一位置参数现状下多词内容本就必须加引号，多参数化不破坏既有用法。
- **空参数即中止，全命令一致**：任何动词的参数经 strip 后为空即报错中止（含批量中的个别空参数），不做静默跳过——由 add 批量场景推广到全部命令（用户拍板）。
- **原子式失败语义**：目标动词先全部解析（ID 全库精确、文本限可见域、多义报错），任一参数失败则整体中止、一条不动，错误列出全部问题参数及候选；add 先校验全部内容再逐条落库。同一命令内重复参数命中本批先建条目（`add 牛奶 牛奶` → 已记录 1 条 + 已存在 1 条）。
- **JSON 契约统一数组**：上述动词的 `--json` 输出从单条目对象改为条目对象数组（单参数也是单元素数组），顺序同参数序；重复回执输出既有条目对象（含取消状态的）。破坏性契约变更，按 ADR-0021 先例接受。
- **人读确认行：单行汇总、按结果分行**：每结果类型一行「已〈结果〉 N 条：[ids]」（如「已记录 2 条：[a] [b]」「已存在 1 条：[c]」），无则不打印；N=1 用同一模板、不回退旧单数文案；末尾照常回显当前域直属列表（ADR-0023 语义不变）。
- **新增第四状态 drop（取消）**：动词 `drop`，JSON status token `dropped`，列表标号 `[-]`，中文显示「已取消」。语义：内容不再适用，但条目保留在库、可逆。
- **终态打点与超龄清理**：`completed_at` 语义从「完成打点、仅 DONE 持有」扩展为「终态打点、终态持有」——drop 时打点（与 finish 同构），reset/pend/finish 离开取消态时清空。清理规则从「仅已完成」扩为「终态（done/dropped）超龄即清」，同一 `retention_days` 配置；待办/进行中永不参与。此条纠正讨论初版「取消条目永不清理」的错误外推（用户裁定：dropped 是另一种 finish 状态，应同样被超龄处理），显式扩展 ADR-0021 确立的清理范围。
- **转移自由，不设守卫**：finish/pend/drop 对已取消条目直接可用，reset→todo 保证可用。
- **add 去重零改动**：去重不分状态——内容与已取消条目重复时照常回执该条目、不自动复原；恢复同名内容须先 reset 旧条目。
- **可见性不隐藏**：已取消条目在 list 与操作回显照常显示，`[-]` 标号 + dim + strike 弱化整行；文本匹配范围不变、不按状态分叉。
- **clear 保持状态盲，drop 无确认**：已取消条目随域清空（确认流程照旧）；drop 可逆、不设确认环节，与 erase 同等待遇。

## 理由

批量统一到全部条目级动词：所有动词共用同一条多参数解析管道，与 ADR-0023「全部动词统一回显」的统一精神一致；只批 add/erase 会立刻造成「一次记多条、删多条，却只能一条条 finish」的不对称，且需维护两套参数形态。原子式失败：erase 是破坏性操作，敲错一个 ID 却删掉其余几条属于意外的部分效果；整体中止符合「失败路径不回显」（ADR-0023）的既有语义，修正后重跑即可。空参数中止：引号失误等意外输入不应被静默吞掉一部分，规则全命令一致才可预期。JSON 数组：输出形状恒定脚本才可写；双形态迫使脚本探测形状，长期负担大于兼容收益。可见性不隐藏：文本匹配本不分状态，隐藏会制造「搜得到但看不见」的幽灵条目（按文本 erase 会删掉列表里没有的东西），违背 ADR-0020「机器可见范围与人读可见范围一致」的原则。去重不分状态：取消也是一种状态，不豁免重复判定；自动复原会让「新 add」悄然变形为状态转移，违背命令字面语义。终态清理：done 与 dropped 同为离开活跃工作流的出口，保留策略没有理由分叉；取消时打点是清理可计时的前提。定名「已取消」而非讨论期提名的「已失效」：取「用户主动撤销适用性」之意，状态中性、可逆——故不隐藏、不设守卫、不设确认。

## Considered Options

- 仅 add/erase 批量、状态动词保持单条：被否——动词间不对称，两套参数形态。
- 尽力而为批量（命中的照做、未命中的报错继续）：被否——破坏性操作的部分执行不可接受，失败汇报形态复杂化。
- JSON 双形态（单参数保持单对象）：被否——形状不定迫使脚本探测。
- 逐条确认行（N 条 = N 行复用现有文案）：被否——用户拍板单行汇总；混合结果以按类型分行补足表达力。
- N=1 回退旧单数文案：被否——统一模板单轨无分支。
- 批量空参数跳过继续：被否——整体中止并推广到全部命令。
- 中文定名「已失效」（讨论期提名）：被否——用户定名「已取消」。
- 已取消条目排除出 add 去重（同名可新建新条目）：被否——去重不分状态。
- 已取消条目默认隐藏（--full 或旗标显示 + 文本匹配排除）：被否——可见范围分裂、幽灵命中。
- 取消设转移守卫（仅可 reset 拉回）：被否——不引入全库第一个转移守卫，保持任意互转模型。
- 取消条目豁免超龄清理（讨论初版外推）：被否——dropped 是另一种 finish 状态，终态保留策略不应分叉。
- 新增独立字段 dropped_at：被否——复用 completed_at 作终态打点，无 schema 变更。
- 取消条目单设保留期：被否——同一 retention_days，终态一视同仁。

## Consequences

- 破坏性 CLI 契约变更：add/erase/finish/pend/reset 的 `--json` 输出单对象 → 数组，旧脚本按对象解析的用法失效——本工具无第三方消费者，按 ADR-0021 先例接受。ADR-0023「回显是人读体验、不进入 JSON 契约」的原则保持不变，本条变更的是条目动词自身输出的形状。
- `completed_at` 语义扩展为终态打点：entry 模型文档需同步改写；JSON 消费方需预期「取消条目携带 completed_at」；字段不改名。
- 新增能力 + 契约变更 → 发布单元需迭代（初步判 minor，版本号由用户确认触发）。
- CONTEXT.md 术语同步：「条目」四态、新增「取消」、「清理」扩为终态规则；「已失效」提名退役入 _Avoid_。
- 帮助文档（app_help / help.md / README）与 i18n 文案需同步新增动词、批量语义、确认行新模板与终态清理规则，实现时一并落地。
- 列表渲染新增第四标号 `[-]` 与 dim + strike 弱化样式（Rich `strike`，SGR 9；Windows Terminal 支持），实现后可视化验证。
- `VERBS` 表新增 `drop`，状态动词分派表扩为四项（finish/pend/reset/drop → 目标状态）；clean() 按 status ∈ {done, dropped} 过滤。
