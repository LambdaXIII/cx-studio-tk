# 领域文档统一为仓库级单套

> 领域：全局 · 适用范围：仓库文档治理

## 背景

本仓库为 uv workspace 单仓，含三个 workspace（`cx-studio` / `cx-wealthy` / `cxalio-studio-tools`）。此前领域文档按 workspace 物理分散：每个包自持 `CONTEXT.md` 与 `docs/adr/`，形成三套并行的 ADR 编号序列。问题：

- **编号歧义**：cx-wealthy 与 cxalio-studio-tools 各有 `ADR-0009`，跨域引用必须带域名限定才能消歧（如「cx-wealthy ADR-0009」）；
- **代码与文档耦合**：代码 docstring 直接引用 ADR 编号（cx_note 三处挂 `ADR-0009`），文档一旦重组编号即撕裂代码；
- **词汇与知识分散**：领域词汇三处维护，处理一个 workspace 需先定位其文档目录。

## 决策

- **D1 布局：仓库级单套**。领域文档统一存放于根 `CONTEXT.md`（按 `## Domain:` 分区）与根 `docs/adr/`（单一编号序列）；适用范围在内容中声明，不靠目录位置区分。删除各 workspace 的 `CONTEXT.md` 与 `docs/adr/`。
- **D2 编号：单一序列**。初始编号按依赖链顺序编排（cx-studio → cx-wealthy → cxalio-studio-tools，组内保持原相对顺序），既成事实见下方映射表；此后新 ADR 一律取最大值 +1 追加，与领域无关，靠顶部「领域/适用范围」标注区分。
- **D3 代码文档独立呈现**。docstring 禁止引用 ADR 编号、`docs/` 路径、issue 编号等仓库外部文档——代码文档自足，IDE 悬停读者不应被要求跳转其他文件；决策背景确有必要时用一句话陈述语义本身。约束单向：文档（CONTEXT/ADR）可引用代码符号，代码不反向引用文档。规范落根 `AGENTS.md`「文档与注释」节。
- **D4 同步边界调整**（同批落实，非领域文档主体）：`.scratch/`（本地 issue/spec 追踪）与 `uv.lock` 加入 `.gitignore`，不再随仓库提交。

## Consequences

- 阅读规则迁移至 `docs/agents/domain.md`：处理某 workspace 先读根 `CONTEXT.md` 对应 Domain 分区与适用 ADR；
- 合并后的 `CONTEXT.md` 分区标题与各 ADR 顶部「领域/适用范围」标注是领域归属的唯一来源；
- cxalio ADR 原 0001 正文互引「见 0007」随迁移改写为「见 0017」；cx_note 代码 docstring 的 ADR 引用已剥离（D3）；
- 本文件是领域文档治理的第一份全局 ADR，后续仓库级文档决策沿用同一序列追加。
