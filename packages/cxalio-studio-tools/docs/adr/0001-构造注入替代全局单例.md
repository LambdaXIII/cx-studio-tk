# 构造注入替代全局单例

旧模式中 Application 通过 `from .appenv import appenv` 直接导入全局单例，导致 Application 绑定到特定 appenv 实例、无法被其他 CLI 工具复用；因此决定改为构造参数注入：Application 通过构造参数接收 appenv，appenv 仍然是单例，但 Application 不绑定它——调用方可以传入任何兼容的 IAppEnvironment。

## Considered Options

- **全局单例导入（旧模式，已否决）**：`from .appenv import appenv` 直接导入。Application 与特定 appenv 实例强绑定，无法复用。

## Consequences

- Application 成为可复用组件，任何调用方都能传入兼容的 `IAppEnvironment`。
- 模块级 appenv 单例仍保留（用于 signal handler 注册等场景，见 `0007`），但 Application 和子组件不再导入使用，改为通过构造参数接收。
- 依赖组装职责转移到入口代码（`__init__.py` 的 `run()`）。
