# cxnote 列表展示：默认折叠 + `--full` 展开 + 每域小表

## 决策

cxnote 人读列表采用**平铺域块**展示，废除树状排列与装饰符号：

- **域块**：域标题行（`cx.note.section` 样式、裸路径字面）外置在表外，其下接该域条目表；域块之间空行分隔。当前工作域非根时列表内**不出现绝对路径**——当前域标题只显示域名字（末段，`/a/b/c` → `c`），根域显示固定标签 `GLOBAL`；下级域标题显示相对当前域的字面并附 `(条目数)`（数量只数该域自身条目，不含孙级）。
- **每域独立无框三列小 `Table`**：标号（`[ ]`/`[~]`/`[x]`，自然宽）、内容（`ratio=1` 撑满；含换行按 Rich Markdown 渲染）、ID 徽章（`width=4`、右对齐贴行尾）各占一列；三列 cell 均为显式 style 的 `Text`/`Markdown`（规避 `say()` 高亮器对 markup 的干扰）。
- **默认折叠，`--full` 展开**：默认当前域条目全显，下级域仅标题行（折叠成目录）；`--full` 时每个下级域标题下接各自条目表。
- **`--full` 同样控制 `--json` 范围**：列表 JSON 默认 = 当前域条目数组；`--full` = 当前域 + 全部下级域扁平数组，顺序与人读一致（不保留树状分组）。
- **徽章样式**：无背景色；8 个高对比 ANSI 亮色（bright_red/green/blue/cyan/magenta/yellow/white + orange1）按字符值定色（同字符同色）；已完成条目徽章随行 dim。

## 理由

v1 初版按「分节标题 + 逐行渲染」整树展开；用户验收返工逐轮拍板：

- 树状排列 + `█`/连接线分节符号在终端观感似乱码，眼球成本高——平铺 + 空行分隔最省眼。
- v1 整表容纳分节标题行，长域字面必然断行割裂列宽（实测触发预定回退）；域标题外置 + 每域独立小表后，标题不再参与列宽计算，Table 容器可回归。
- 深域 + 多级下级的全展开视图淹没当前工作域——默认折叠把焦点留给当前域，展开是显式请求（`--full`）。
- 机器契约必须与人读视图的「可见范围」一致——脚本看到的应与终端用户看到的是同一份真相，否则同一命令两种语义。
- 标题相对化 + 名字化：当前工作域是现场，全路径与绝对前缀不携带增量信息、只占行宽；`GLOBAL` 给根域一个可读的固定名。

## Considered Options

- **树状缩进 + `█`/连接线**：被用户否决（视觉噪声似乱码）→ 平铺域块。
- **单一大 Table 含分节标题行**：v1 实测分节行断行破坏列宽 → 域标题外置，每域独立小表规避根因。
- **逐行 Group 渲染**（v1 回退态）：列对齐与徽章右缘靠手工 padding 维持、脆弱 → 每域 Table 重新接管列分配（本设计优于 v1）。
- **`-e/--expand` 短参数**：被否——定名 `--full`，语义是「完整视图」而非「展开动画」；参数名与 `--json` 联动语义一并定案。
- **JSON 契约不变**（列表恒含全部下级）：被否——`--full` 影响 `--json` 范围是用户拍板的机器契约变更。
- **徽章 `on grey15` 深灰底**：被否（色块观感脏、低对比）→ 无底色高对比亮色。
- **当前域标题显示全路径**：被否 → 名字（末段）；根域字面 `/` 无信息量 → 固定标签 `GLOBAL`。

## Consequences

- **`--json` 默认返回值语义变化**（相对 v1）：列表默认仅当前域条目数组；脚本消费全量需加 `--full`。冒烟断言与 spec issue #1 已同步。
- 折叠态下级域只有标题行——想看子域条目必须 `--full`（人读与 JSON 同规则）。
- 多行 Markdown 进 Table 内容列是新引入的渲染风险面：经 SVG 预览核检无破格/列重叠/错位；若未来特定内容触发破版，回退预案为多行条目改两行式（首行标号 + 徽章，次行内容列 Markdown），单行条目维持三列行。
- 徽章「值定色」继承 v1：同一字符在所有 ID 中同色，ID 内重复字符同色——后果已确认接受。
- 相对字面切割基于 canonical 长度（canonical 即 `lower()`，与字面同长），大小写不敏感场景切割安全：当前 `/ab`、子域 `/aB/c` → 显示 `/c`。
