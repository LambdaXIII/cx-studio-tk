# 通用核心与特化分层

`document/` 是通用复合树核心（`Node`/`Group`/`Note`/`WealthyDocument`），`help/` 是帮助系统特化层（`Action`/`WealthyHelp` 继承 `WealthyDocument`）。决定保持两层分离：通用核心不知道 flags/nargs/usage 为何物——合并两者会导致通用核心的稳定性被 help 的迭代绑架，且通用复合树被封装在 help 内部时，使用方不会想到它还能渲染非帮助类的结构化文档，能力被埋没。

## Considered Options

- **不分层，全部塞在 help/ 里**：通用核心的稳定性被 help 的迭代绑架——help 一变通用核心就要跟着变；通用复合树被封装在 help 内部时，使用方不会想到它还能渲染非帮助类结构化文档。

## Consequences

- `document/` 保持稳定、小步演进，任何"分组 + 条目 + 注释"的结构化输出（不限于帮助）都基于它构建。
- 新特化层（如非帮助类的结构化文档）同样以 `document/` 为基，不重复实现复合树。
