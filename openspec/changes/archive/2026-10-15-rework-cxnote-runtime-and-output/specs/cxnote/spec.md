# Spec Delta

## Purpose

按 cxnote 的真实模型重排三层：条目是自足的呈现单元（不再拼进按域共享的表格）、一次运行有明确阶段（动词只改内存工作集，超龄清理与落盘收归收尾）、回显报告本次变更条目（不再是当前域现场）。同时补上 `edit`（覆盖条目内容）与即将被清理条目的呈现标记。磁盘格式不变。

## MODIFIED Requirements

### Requirement: 全部条目存于单个 JSON 文件并原子重写

全部条目 MUST 存入单个 JSON 文件（`notes.json`，位于用户配置目录的 CxNote 下），文件内容 MUST 是条目对象的裸 JSON 数组。一次运行 MUST 至多在**收尾阶段**落盘一次：以临时文件加原子替换整文件重写，写出的内容 MUST 反映该次运行中全部已完成的变更（含收尾的超龄清理）；工作集与读盘结果一致时 MUST NOT 写盘。运行在到达收尾之前结束（错误中止、用户中断）时 MUST NOT 写条目存储文件，该文件 MUST 保持运行前的内容（配置文件的缺省初始化发生在初始化阶段，不在此列）。文件不存在时按空库启动且不主动创建文件；文件存在但无法完整解析（JSON 非法、条目缺键、时间戳或状态值非法、IO 错误）时 MUST 报错中止且 MUST NOT 静默清空或覆盖。加载时无法识别的 status token MUST 容错归一为 `todo`，时间戳非法仍按损坏处理。

#### Scenario: 写操作的原子重写

- **WHEN** 一次运行中执行 `add a b`，且收尾的超龄清理又清除了 1 条条目
- **THEN** 存储文件以整文件重写方式更新一次，内容同时反映两条新增与那条清除，不存在写一半的中间态

#### Scenario: 中途失败不落盘

- **WHEN** 运行在处理业务阶段因错误中止（如目标动词的某个参数无命中）
- **THEN** 存储文件保持运行前的内容，本轮已完成的其它变更一并放弃

#### Scenario: 存储损坏时拒载拒写

- **WHEN** notes.json 存在但内容无法解析为合法条目集
- **THEN** 命令报错中止，不执行任何写操作，不删除或重建该文件

#### Scenario: 未知状态 token 容错

- **WHEN** 存储文件中某条目的 status 值不是现行四态之一（如历史遗留 token）
- **THEN** 该条目按 `todo` 加载并在下次保存时回写为 `todo`，不判为损坏

### Requirement: 统一命令面与批量参数

cxnote 命令面 MUST 由九个动词构成：`add`（记录）、`list`（查看，不带动词时缺省执行）、`edit`（覆盖条目内容）、`finish` / `pend` / `reset` / `drop`（状态流转）、`erase`（删除单条）、`clear`（清空域）。批量动词（`add` 与 `finish` / `pend` / `reset` / `drop` / `erase`）MUST 支持不定项参数、每参数一条；`edit` MUST 恰好接收两个参数（目标条目与新内容）；`clear` 为域级动作、无目标参数。MUST NOT 为任何已移除的历史动词提供别名。参数经去除首尾空白后为空的条目 MUST 整体报错中止，不做静默跳过。目标动词 MUST 原子式执行：先解析全部参数，任一参数失败则整体中止、一条不动，错误信息 MUST 列出全部失败参数及其候选；`add` MUST 先完成全部内容的去重判定再逐条落库。

#### Scenario: 批量状态流转

- **WHEN** 以 `finish <id1> <文本片段>` 指定两个目标执行
- **THEN** 两个条目一次性全部转为已完成，确认与输出按去重后的目标数陈述

#### Scenario: 原子式失败

- **WHEN** 目标动词的参数列表中第二项无法命中任何条目
- **THEN** 整体报错中止，列出第二项的失败原因，第一项目标不被处理

#### Scenario: 空参数中止

- **WHEN** 任意动词的参数列表中出现 strip 后为空的参数（如引号失误）
- **THEN** 报错中止并列出空参数位置，不执行任何部分操作

#### Scenario: 缺省动词

- **WHEN** 不带动词直接运行 cxnote
- **THEN** 等价于执行 `list`

#### Scenario: 帮助先于副作用

- **WHEN** 以 `-h` 或 `--tutorial` 运行
- **THEN** 输出帮助或教程，不初始化配置文件、不读写存储

#### Scenario: edit 的参数个数固定

- **WHEN** 以 1 个参数或 3 个参数执行 `edit`
- **THEN** 报错中止，不修改任何条目

### Requirement: 目标定位规则与重复目标去重

目标动词的每个参数 MUST 按固定规则定位条目：4 位 ID 在全库范围精确匹配；非 ID 参数在可见域（当前域及其下级域）内做内容大小写不敏感的子串匹配。零命中与多义命中 MUST 记入失败清单；多义时 MUST 列出全部候选条目，且每个候选 MUST 以条目块呈现。同一目标无论以 ID、文本片段还是两者混写出现多次，MUST 只保留首次出现的解析结果——确认行计数与 JSON 数组长度均等于去重后的目标数，并与实际处理的条目一一对应。

#### Scenario: ID 与文本的不同定位范围

- **WHEN** 以 4 位 ID 指定下级域条目，以文本片段指定当前域条目
- **THEN** 两者均成功命中；同一文本片段在可见域内命中多条时报错并列出候选

#### Scenario: 重复目标去重

- **WHEN** 以 `finish <id> <id>`（或 ID 与同一文本混写）执行
- **THEN** 该条目只被处理一次，确认计数与输出数组长度均为 1

#### Scenario: 多义候选以条目块呈现

- **WHEN** 文本片段在可见域内命中多条，其中一条内容超过终端一行宽度
- **THEN** 候选逐条以条目块输出，超长内容折行呈现而不截断

### Requirement: 终态条目超龄自动清理

超龄清理 MUST 作为每次运行**收尾阶段**的维护自动执行，MUST NOT 提供手动清理命令：凡到达读盘的运行都在收尾执行一次清理——包括业务阶段未产生变更但正常结束的运行（如 `clear` 拒绝确认）；在读盘之前就结束的运行（帮助路由、参数错误中止）不在其列。作用域为当前工作域及其下级域，仅清除终态（`done` / `dropped`）且终态打点时间超过保留天数的条目；待办与进行中条目永不参与。保留天数 MUST 仅经配置文件 `retention_days` 调整（缺省 30 天，配置文件缺失时首次运行自动初始化）；配置文件损坏或 `retention_days` 非整数 MUST 报错中止；`retention_days` 不大于 0 时 MUST 视为禁用清理。清理是尽力而为的本地维护，未回访域的超龄条目允许滞留。

清理实际清除了条目时，人读模式 MUST 报告本次清理——**独立于业务输出的一段**，位置在业务输出（确认行与变更条目）之后，形态与业务回显一致（确认行 + 被清条目的条目块，按所属域分块）；`--json` 模式 MUST NOT 输出清理报告。

#### Scenario: 终态超龄清除

- **WHEN** 当前域子树内存在打点时间超过保留天数的已完成与已取消条目，任意运行一次 cxnote
- **THEN** 这些终态条目在收尾阶段被清除，待办与进行中条目不受影响

#### Scenario: 只读运行也执行清理

- **WHEN** 以 `list` 运行，且当前域子树内存在超龄终态条目
- **THEN** 这些条目仍被清除，本次运行照常落盘

#### Scenario: 清理的报告形态

- **WHEN** 人读模式下一次运行清除了 2 条超龄条目
- **THEN** 在变更条目的回显之后输出确认行与这 2 条的条目块；同一操作以 `--json` 运行时 stdout 不含清理报告

#### Scenario: 拒绝确认的运行仍执行清理

- **WHEN** 人读模式执行 `clear` 并拒绝确认，而当前域子树内存在超龄终态条目
- **THEN** `clear` 不删除任何条目，但收尾的超龄清理照常执行并报告

#### Scenario: 配置损坏中止

- **WHEN** 配置文件存在但 `retention_days` 不是整数
- **THEN** 命令报错中止，不执行任何读写

### Requirement: list 的平铺域块与折叠展示

人读列表 MUST 以平铺域块展示：每域一个标题行，其下为该域的条目块；域块间以空行分隔，MUST NOT 使用树状缩进或装饰符号。默认 MUST 折叠：当前域条目全显，下级域仅显示标题行；`--full` 时每个下级域标题下接各自条目块。当前域标题 MUST 只显示域名字（末段），根域显示固定标签 `GLOBAL`；下级域标题显示相对当前域的字面并附该域自身条目数（不含孙级）。域标题 MUST 以主题样式表中登记的专属样式名呈现，渲染代码 MUST NOT 内联样式属性。当前工作域非根时，列表 MUST NOT 出现绝对路径。列表分组 MUST 当前域组在前、其余按域身份排序，组内按创建时间升序。已取消条目 MUST 照常显示并以弱化样式（变暗加删除线）标识，已完成条目徽章随行变暗。当前域无条目时 MUST 输出空态提示，不静默。

#### Scenario: 默认折叠与展开

- **WHEN** 当前域及其下级域各有条目，分别以默认参数与 `--full` 执行 `list`
- **THEN** 默认输出中下级域仅有标题行；`--full` 输出中下级域条目块全部展开

#### Scenario: 标题相对化

- **WHEN** 当前域为 `/a/b`，其下级域 `/a/b/c` 有 2 条条目
- **THEN** 列表中当前域标题显示 `b`，下级域标题显示 `/c (2)`，不出现 `/a/b` 全路径

#### Scenario: 根域标签

- **WHEN** 以 `-g` 执行 `list`
- **THEN** 当前域标题显示 `GLOBAL`

#### Scenario: 已取消条目的可见与弱化

- **WHEN** 列表或回显中存在已取消条目
- **THEN** 该条目以 `[-]` 标号正常显示，整行以变暗加删除线弱化；文本定位仍可命中它

### Requirement: JSON 机器契约

`--json` 模式 MUST 向 stdout 输出纯净 JSON（无标题、确认行、回显等任何装饰文本）。条目级动词 MUST 输出条目对象数组（单参数也是单元素数组），顺序同参数序；`clear` MUST 输出被清条目数组；`list` MUST 输出扁平条目数组，默认仅当前域条目，`--full` 时为当前域及全部下级域且顺序与人读视图一致。条目对象 MUST 全量携带 `id` / `domain` / `content` / `status` / `created_at` / `completed_at` 六键，`completed_at` 为空时 MUST 为 `null` 而非缺键；在任何输出条目对象的场合，即将被清理的条目 MUST 另行携带 `expiring` 键（真值），其余条目 MUST NOT 携带该键。失败路径的退出语义 MUST 与人读模式一致。

#### Scenario: 条目动词输出数组

- **WHEN** 以 `--json` 执行 `finish <id>`
- **THEN** stdout 仅为一个含单元素条目对象的数组，该对象六键齐备

#### Scenario: list 输出范围与 --full 联动

- **WHEN** 当前域及下级域各有条目，分别以默认参数与 `--full` 执行 `list --json`
- **THEN** 默认数组仅含当前域条目；`--full` 数组含下级域条目且顺序与人读一致

#### Scenario: 纯净 stdout

- **WHEN** 以 `--json` 执行任何成功的写动词
- **THEN** stdout 仅含 JSON 文本，确认行、列表回显、标题横幅均不出现

#### Scenario: 即将被清理的标记键

- **WHEN** 以 `--json` 执行 `list`，其中一条为即将被清理的条目
- **THEN** 该条目对象带 `expiring: true`，其余条目对象只有六键

## REMOVED Requirements

### Requirement: 操作后回显当前域现场

**Reason**: 回显按"当前域全量清单"组织，操作结果被淹在整域条目里；而 ID 是全库定位，被命中的条目落在别的域时，回显里根本看不到它——操作成功却看不见效果。回显改为按本次变更条目组织。

**Migration**: 替代契约由 ADDED Requirement「操作后回显本次变更条目」承载：确认行的句式与分行规则、失败路径不回显、`--json` 不回显这些要求原样保留；确认行中 ID 的形态由方括号包裹改为裸 4 位 ID，与条目块中的 ID 形态一致；回显内容由"当前域直属条目列表"改为"本次变更条目，按所属域分块"。

## ADDED Requirements

### Requirement: 条目块是条目在终端的呈现单元

每条条目在终端 MUST 呈现为一个**条目块**：首部依次为 4 位 ID 徽章与状态标号（**ID 在前**；标号为 `[ ]` 待办 / `[~]` 进行中 / `[x]` 已完成 / `[-]` 已取消），两者定宽；其后为条目内容。条目块 MUST 自足——呈现 MUST NOT 依赖跨条目对齐，MUST NOT 把多条条目拼进同一个共享表格。

内容在一行放不下时 MUST 在块内折行并完整呈现，MUST NOT 截断或以省略号省略；内容含多个源行时 MUST 逐行呈现（MUST NOT 折叠为一行）；折行的续行与多行内容的每个源行 MUST 与内容列对齐。

任何呈现条目的场合（列表、操作后回显、定位候选、清理报告）MUST 使用条目块，MUST NOT 另立截断预览形态。

#### Scenario: 超长内容折行不截断

- **WHEN** 一条条目的内容超过终端一行宽度
- **THEN** 内容在条目块内折行完整呈现，续行与内容列对齐，不出现省略号截断

#### Scenario: 多行内容逐行呈现

- **WHEN** 条目内容含三个真实换行（源行三行）
- **THEN** 输出为三行，每行与内容列对齐，不被折叠成一行

#### Scenario: 呈现形态唯一

- **WHEN** 同一条目分别出现在列表、操作后回显与定位候选中
- **THEN** 三处呈现为同一形态的条目块

### Requirement: edit 覆盖条目内容

`edit` MUST 以 `TARGET CONTENT` 两个参数调用：第一参数按「目标定位规则与重复目标去重」定位单条条目，第二参数为新内容。执行后该条目的内容 MUST 被新内容覆盖（参数中的字面 `\n` MUST 转换为真实换行，与 `add` 一致）；该条目的状态、所属域、ID、创建时间与终态打点 MUST NOT 改变。`edit` MUST NOT 做去重或撞车校验——改出的内容与同域其它条目相同时 MUST 照常成功；新内容与原文相同时 MUST 照常按一次变更处理——照常打印确认行、照常进入回显，但工作集与读盘结果一致，故不落盘。`edit` MUST 计入本次变更条目。

#### Scenario: 覆盖内容不影响其它字段

- **WHEN** 对一条终态条目执行 `edit <id> "新的内容"`
- **THEN** 内容更新，状态仍为原终态且终态打点时间不变，ID 与所属域不变

#### Scenario: 允许改出重复内容

- **WHEN** 把条目 A 的内容改成与同域条目 B 完全相同
- **THEN** 修改成功，域内存在两条内容相同的条目

### Requirement: 即将被清理的条目标记

**即将被清理**指本次运行的收尾阶段会因超龄而被清除的条目——仍留在工作集中、落在清理作用域（当前工作域及其下级域）内、且满足「终态条目超龄自动清理」所列清除条件者。被本次操作取走的条目（`erase` / `clear` 的输出）不在其列：收尾不会再清除它们。该判定 MUST 按当前工作集与本次运行生效的保留天数即时计算，MUST NOT 固化进条目、MUST NOT 写入存储。

- 人读呈现：即将被清理条目的条目块 MUST 带一个词形标记（文案「即将被清理」），与其它条目相区分。
- `--json` 呈现：即将被清理的条目对象 MUST 携带 `expiring` 键（真值）。

#### Scenario: 列表中标出即将被清理的条目

- **WHEN** 当前域内 3 条条目中 1 条为即将被清理
- **THEN** 该条目的条目块带「即将被清理」标记，另两条不带

#### Scenario: 离开终态后标记消失

- **WHEN** 对一条即将被清理的条目执行 `reset`（转回待办）
- **THEN** 本次运行的收尾不清除它，呈现中也不带标记

### Requirement: 操作后回显本次变更条目

人读模式下，写动词产生的变更条目 MUST 在确认行之下按条目所属域分块呈现：块内条目呈现为条目块；域标题与相对化规则同 `list`，当前域子树之外的域 MUST 用绝对字面作标题，即使只有单一域块该标题也 MUST 打印。域块之间 MUST 当前域子树居前、其余按域身份排序；块内条目 MUST 按本次操作的处理顺序呈现；MUST NOT 再打印当前域的全量清单。

条目级动词的批量确认行 MUST 采用模板「已〈结果〉 N 条：〈ID 列表〉」——裸 4 位 ID、空格分隔，单数与复数同一模板，无结果的类型不打印；`clear` 是域级动作，确认句式为「已清空 N 条条目。」。本次运行没有变更条目时 MUST NOT 输出空的回显区块；错误中止路径（无命中、多义、空参数）MUST 维持纯错误输出、不回显；`--json` 模式 MUST NOT 输出回显。

#### Scenario: 当前域内的状态流转回显

- **WHEN** 人读模式对当前域的两条条目执行 `finish <id1> <id2>`
- **THEN** 输出确认行，其下按当前域分块呈现这两条条目的已完成形态

#### Scenario: 跨域命中的条目照常回显

- **WHEN** 在当前域 `/a` 下以 ID 对域 `/x/y` 的条目执行 `finish`
- **THEN** 回显按 `/x/y` 分块（以绝对字面作域标题）呈现该条目

#### Scenario: add 的新建与回执都在回显内

- **WHEN** 执行 `add 牛奶 牛奶`（第二条命中已存在）
- **THEN** 回显按参数序呈现两条条目：新建的一条与回执的既有条目

#### Scenario: 失败不回显

- **WHEN** 目标动词因多义命中报错中止
- **THEN** 输出仅含错误信息与候选条目块，不打印任何变更条目回显

#### Scenario: 被取走的条目按取走前状态呈现

- **WHEN** 人读模式对一条已完成条目执行 `erase`（或对当前域执行 `clear`）
- **THEN** 回显按该条目所属域分块呈现它，标号为取走前的 `[x]`

#### Scenario: edit 后回显新内容

- **WHEN** 人读模式对一条条目执行 `edit <id> "新的内容"`
- **THEN** 确认行为「已修改 1 条：〈id〉」，其下呈现内容已更新的条目块

#### Scenario: 无变更条目时不输出空块

- **WHEN** 人读模式执行 `clear` 后拒绝确认
- **THEN** 不打印任何回显区块（收尾的清理报告若有则另段输出）
