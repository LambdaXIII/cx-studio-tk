# Proposal

## Why

cxnote 的三层实现都建在错误前提上：条目被当成**共享表格里的行**（于是超长内容被截断、多行内容被压成一行）、回显被当成**当前域现场打印**（于是操作结果被淹在整域清单里，跨域命中的条目根本看不见）、落盘被当成**每个动作各自的收尾**（于是"用户没看到的结果"会被写进磁盘）。三者同一个根因：工具的真实模型是"全局单库 + 域只是条目的字面标签 + 一次运行有明确阶段"，实现没有对应到这个模型。顺带补上缺失的 `edit`——现在改一个错字只能 `erase` 后重新 `add`，丢 ID、丢状态、丢创建时间。

## What Changes

- **运行阶段显式化**：一次运行 = 初始化 → 读盘 → 处理业务 → 收尾。动词只在内存**工作集**上操作（`erase` 是 take——从工作集取出并把条目对象交出来，供回显使用）；**超龄清理与落盘收归收尾**，整个 run 只做一次原子重写。异常与中断路径不进收尾，磁盘保持运行前的状态。
- **条目成为自足渲染单元**：一条条目 = 一个 `ID 标号 内容` 的块，不再拼进按域共享的表格。由此：
  - 超长内容**折行不截断**——现行实现把长内容以 `…` 截断，是缺陷
  - 多行内容**逐行呈现**、续行与内容列对齐——现行实现经 Markdown 软换行把多行压成一行，是缺陷
  - 任何需要展示条目的场合（列表、回显、定位歧义的候选清单）都用同一套条目渲染，不再有各自的特例形态
- **写动词回显 = 本次变更条目**（取代现行"回显当前域现场"）：按条目所属域分块呈现；ID 是全局定位，跨域命中的条目照常出现在回显里。整域回显取消。
- **新增 `edit TARGET CONTENT`**（命令面八动词 → 九动词）：只覆盖条目内容，不动状态、不动所属域、不重置终态打点。
- **超龄条目的可见性**：本次收尾会因超龄被清掉的条目，在任何呈现中带「**即将被清理**」标记（人读一个词、`--json` 一个键）；收尾的清理动作在业务输出之后按同一形态单独报告（确认行 + 条目块）。
- **域标题的样式：登记已存在（`cx.note.section`），本次只改取值**（`bold` → `bold yellow`），并删除全仓无引用的 `cx.note.id`；渲染代码不内联样式字面量。
- **人读输出形态变化，脚本契约不变**：`--json` 的六键仍全量在场（即将被清理的条目另加一个键）、退出码语义维持原样。
- **磁盘格式零变化**：`notes.json` 仍是裸 JSON 数组——不加版本头、不加域表。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `cxnote`: delta 为 **6 MODIFIED + 1 REMOVED + 4 ADDED**。MODIFIED：列表展示（条目自足渲染：不截断、多行真多行、域标题走登记样式）、目标定位（多义候选改用条目块呈现）、命令面（八动词 → 九动词，`edit` 恰两个参数）、存取（落盘时机由"每次写操作"改为"运行收尾一次原子重写"）、超龄清理（执行时机由"写操作附带"改为"每次运行的收尾阶段"，并新增清理报告）、JSON 机器契约（新增条件的 `expiring` 键）；REMOVED：操作后回显当前域现场；ADDED：条目块是条目在终端的呈现单元、`edit` 覆盖条目内容、即将被清理的条目标记、操作后回显本次变更条目。

## Impact

- **代码**：`packages/cxalio-studio-tools/cx_note/` —— `application.py`（阶段编排、回显重构、`edit` 动词、`--json` 输出投影）、`components/list_view.py`（条目块渲染，去共享表、去截断）、`common/note_store.py`（去掉各写方法里的落盘与 `clean()`，改为工作集 + 显式落盘入口）、`common/expiry.py`（新增即将被清理的判据）、`appcontext.py`（`VERBS` 加 `edit`）、`appenv.py`（样式表）、`app_help.py` 与 `help.md` / `help.en_US.md`（九动词）、`i18n/locales/cx-note.pot` 与 `en_US/LC_MESSAGES/cx-note.po` / `.mo`（新增文案，不生成 `zh_CN`）；`common/entry.py` **不改**（`entry_to_json` 保持持久化形态，`expiring` 由 application 层投影时附加）
- **规格**：`openspec/specs/cxnote/spec.md` —— 见 delta specs
- **文档**：根 `CONTEXT.md` 的 `Domain：cxalio-studio-tools` 分区（cx-note 的词条在该分区的术语表里，仓库没有独立的 cxnote 分区）——新增术语（条目块、即将被清理、变更条目），并更新"清理"词条的执行时机（写操作附带 → 每次运行的收尾阶段）与作用域（该词条现写"仅限当前域"，与 spec 的"当前域及其下级域"不符，以 spec 为准）
- **依赖**：无新增第三方依赖
- **版本**：**minor → 1.4.0**（用户拍板）。迭代起点取 pyproject 现值 1.3.0（`cx_note.__version__` 的 1.2.0 只是该包上次变更时的版本快照，不是迭代起点）。本次虽改动了 `cx_note.common` 已导出符号 `NoteStore` 的写方法契约（写方法不再自行落盘、`clean()` 移除），但该能力层只在工具包内部被消费、仓库内无外部使用方，按"单点能力面变化"判 minor
