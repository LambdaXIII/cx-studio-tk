# Spec Delta

## Purpose

定义 cxnote CLI（终端快速便签）的现行行为契约：域的字面命名空间语义、单 JSON 存储、条目四态状态机、命令面与批量语义、删除与自动清理规则、列表展示、机器可读输出与操作后回显。

## ADDED Requirements

### Requirement: 域是字面命名空间

cxnote 的域 MUST 是纯字符串的字面命名空间：以 `/` 开头、不以 `/` 结尾的路径式字面（根域为 `/`），仅用作条目归属的组织单位，MUST NOT 映射到文件系统目录结构。域身份判定 MUST 大小写不敏感，存储 MUST 保留首次出现的原始字面，后续不同大小写的访问映射到同域且不改写既有字面。当前工作域默认从工作目录推导（HOME 之下取相对字面，HOME 即根域，HOME 之外取去盘符绝对字面）；`-p/--path` 以 `/` 开头时为绝对域，否则相对当前域；`-g/--global` 表示根域。域的包含关系按段判定，`/生活琐事2` 与 `/生活琐事` 互不包含。

#### Scenario: 不同大小写访问同一域

- **WHEN** 条目已记录在域 `/Work`，随后在域 `/work` 下执行写操作
- **THEN** 操作落在同一条目集合上，且已有条目的域字面保持 `/Work` 不被改写

#### Scenario: 从工作目录推导当前域

- **WHEN** 未指定域选项时在工作目录 `$HOME/projects/film` 下执行任意动词
- **THEN** 当前工作域为 `/projects/film`

#### Scenario: 域选项指定工作域

- **WHEN** 以 `-p 子域` 执行动词，且当前域为 `/a`
- **THEN** 该动词的工作域为 `/a/子域`；以 `-p /x` 或 `-g` 执行时工作域分别为 `/x` 与根域

#### Scenario: 跨盘符同字面合并

- **WHEN** 分别在 `C:\work\proj` 与 `D:\work\proj` 下记录条目
- **THEN** 两组条目归属同一个域（字面命名空间不携带盘符语义）

### Requirement: 全部条目存于单个 JSON 文件并原子重写

全部条目 MUST 存入单个 JSON 文件（`notes.json`，位于用户配置目录的 CxNote 下），每次写操作 MUST 以临时文件加原子替换整文件重写。文件不存在时按空库启动且不主动创建文件；文件存在但无法完整解析（JSON 非法、条目缺键、时间戳或状态值非法、IO 错误）时 MUST 报错中止且 MUST NOT 静默清空或覆盖。加载时无法识别的 status token MUST 容错归一为 `todo`，时间戳非法仍按损坏处理。

#### Scenario: 写操作的原子重写

- **WHEN** 任意写操作（记录、转移、删除、清空、清理）成功执行
- **THEN** 存储文件以整文件重写方式更新，不存在写一半的中间态

#### Scenario: 存储损坏时拒载拒写

- **WHEN** notes.json 存在但内容无法解析为合法条目集
- **THEN** 命令报错中止，不执行任何写操作，不删除或重建该文件

#### Scenario: 未知状态 token 容错

- **WHEN** 存储文件中某条目的 status 值不是现行四态之一（如历史遗留 token）
- **THEN** 该条目按 `todo` 加载并在下次保存时回写为 `todo`，不判为损坏

### Requirement: 条目四态与自由转移状态机

每条条目 MUST 携带：字符串内容（可含真实换行）、四态状态之一（JSON token 为 `todo` / `pending` / `done` / `dropped`，显示名为待办/进行中/已完成/已取消）、创建时间、终态打点时间、所属域与全库唯一的 4 位小写 base36 ID（生成后终身不变）。`done` 与 `dropped` 为终态。任意状态间 MUST 可自由转移、不设守卫：`finish` 转 `done`，`pend` 转 `pending`，`reset` 转 `todo`，`drop` 转 `dropped`。条目进入任一终态时 MUST 记录终态打点时间，离开终态时 MUST 清空该打点。

#### Scenario: 状态转移与终态打点

- **WHEN** 对待办条目执行 `finish`，随后对它执行 `reset`
- **THEN** 条目状态变为 `done` 且记录终态打点；重置后状态回到 `todo` 且终态打点被清空

#### Scenario: 取消条目可再转移

- **WHEN** 对已取消（`dropped`）条目直接执行 `finish`、`pend` 或 `drop` 之外的 `reset`
- **THEN** 转移成功，不要求先经过任何中间状态

### Requirement: 统一命令面与批量参数

cxnote 命令面 MUST 由八个动词构成：`add`（记录）、`list`（查看，不带动词时缺省执行）、`finish` / `pend` / `reset` / `drop`（状态流转）、`erase`（删除单条）、`clear`（清空域）。条目级动词（`add` 及五个目标动词）MUST 支持不定项参数、每参数一条；`clear` 为域级动作、无目标参数。MUST NOT 为任何已移除的历史动词提供别名。参数经去除首尾空白后为空的条目 MUST 整体报错中止，不做静默跳过。目标动词 MUST 原子式执行：先解析全部参数，任一参数失败则整体中止、一条不动，错误信息 MUST 列出全部失败参数及其候选；`add` MUST 先完成全部内容的去重判定再逐条落库。

#### Scenario: 批量状态流转

- **WHEN** 以 `finish <id1> <文本片段>` 指定两个目标执行
- **THEN** 两个条目一次性全部转为已完成，确认与输出按去重后的目标数陈述

#### Scenario: 原子式失败

- **WHEN** 目标动词的参数列表中第二项无法命中任何条目
- **THEN** 整体报错中止，列出第二项的失败原因，第一项目标不被处理

#### Scenario: 空参数中止

- **WHEN** 任意动词的参数列表中出现 strip 后为空的参数（如引号失误）
- **THEN** 报错中止并列出空参数位置，不执行任何部分操作

#### Scenario: 缺省动词

- **WHEN** 不带动词直接运行 cxnote
- **THEN** 等价于执行 `list`

#### Scenario: 帮助先于副作用

- **WHEN** 以 `-h` 或 `--tutorial` 运行
- **THEN** 输出帮助或教程，不初始化配置文件、不读写存储

### Requirement: 目标定位规则与重复目标去重

目标动词的每个参数 MUST 按固定规则定位条目：4 位 ID 在全库范围精确匹配；非 ID 参数在可见域（当前域及其下级域）内做内容大小写不敏感的子串匹配。零命中与多义命中 MUST 记入失败清单（多义时列出全部候选条目）。同一目标无论以 ID、文本片段还是两者混写出现多次，MUST 只保留首次出现的解析结果——确认行计数与 JSON 数组长度均等于去重后的目标数，并与实际处理的条目一一对应。

#### Scenario: ID 与文本的不同定位范围

- **WHEN** 以 4 位 ID 指定下级域条目，以文本片段指定当前域条目
- **THEN** 两者均成功命中；同一文本片段在可见域内命中多条时报错并列出候选

#### Scenario: 重复目标去重

- **WHEN** 以 `finish <id> <id>`（或 ID 与同一文本混写）执行
- **THEN** 该条目只被处理一次，确认计数与输出数组长度均为 1

### Requirement: add 的去重回执与换行转换

`add` 将每条参数作为一条条目内容记录到当前域。参数中的字面 `\n` MUST 逐参数转换为真实换行。当目标域中已存在内容完全相同的条目时 MUST NOT 重复记录，而是回执该既有条目（不因状态不同豁免，也不自动复原已取消条目）；同一批次内先建的条目对后续同内容参数生效（`add 牛奶 牛奶` 回执一条新建与一条已存在）。输出的条目数组 MUST 按参数序排列，新建与已存在回执混排于同一数组。

#### Scenario: 同内容回执既有条目

- **WHEN** 当前域已有内容为「买菜」的已取消条目，执行 `add 买菜`
- **THEN** 不新建条目，回执既有已取消条目且其状态保持不变

#### Scenario: 批内去重

- **WHEN** 执行 `add 牛奶 牛奶`
- **THEN** 第一条新建、第二条回执已存在，共落库一条

#### Scenario: 换行转换

- **WHEN** 执行 `add "买菜\n做饭"`
- **THEN** 落库内容含真实换行，展示时按多行内容渲染

### Requirement: 删除与清空的双轨模型

`erase` MUST 物理删除被定位的单条条目（批量时逐条删除、原子式），被删条目不可恢复。`clear` MUST 清空当前工作域的直属条目（不含子域）且状态盲（已取消条目一并清除）：人读模式下 MUST 先报告目标域与条目数并请求确认，仅确认后才执行；`--json` 模式 MUST 跳过确认直接执行并输出被清条目数组。目标域无条目时 MUST 直接回执空域，不请求确认。`drop` 可逆，MUST NOT 设置确认环节。

#### Scenario: 清空当前域

- **WHEN** 当前域有 3 条直属条目（含子域 2 条不被计入），人读模式执行 `clear` 并输入 `y`
- **THEN** 报告将清空 3 条，确认后仅这 3 条被移除，子域条目保留

#### Scenario: 脚本通道跳过确认

- **WHEN** 以 `--json` 执行 `clear`
- **THEN** 不请求确认，直接清空并输出被清条目数组

#### Scenario: 拒绝确认

- **WHEN** 人读模式执行 `clear` 后未输入 `y`
- **THEN** 不删除任何条目，输出取消提示

### Requirement: 终态条目超龄自动清理

超龄清理 MUST 作为写操作的附带维护自动执行，MUST NOT 提供手动清理命令。作用域为当前工作域及其下级域，仅清除终态（`done` / `dropped`）且终态打点时间超过保留天数的条目；待办与进行中条目永不参与。保留天数 MUST 仅经配置文件 `retention_days` 调整（缺省 30 天，配置文件缺失时首次运行自动初始化）；配置文件损坏或 `retention_days` 非整数 MUST 报错中止；`retention_days` 不大于 0 时 MUST 视为禁用清理。清理是尽力而为的本地维护，未回访域的超龄条目允许滞留。

#### Scenario: 终态超龄清除

- **WHEN** 当前域子树内存在打点时间超过保留天数的已完成与已取消条目，执行任意写操作
- **THEN** 这些终态条目被自动清除，待办与进行中条目不受影响

#### Scenario: 配置损坏中止

- **WHEN** 配置文件存在但 `retention_days` 不是整数
- **THEN** 命令报错中止，不执行任何读写

### Requirement: list 的平铺域块与折叠展示

人读列表 MUST 以平铺域块展示：每域一个标题行加一个无框三列表（状态标号列、内容列、ID 徽章列），域块间以空行分隔，MUST NOT 使用树状缩进或装饰符号。默认 MUST 折叠：当前域条目全显，下级域仅显示标题行；`--full` 时每个下级域标题下接各自条目表。当前域标题 MUST 只显示域名字（末段），根域显示固定标签 `GLOBAL`；下级域标题显示相对当前域的字面并附该域自身条目数（不含孙级）。当前工作域非根时，列表 MUST NOT 出现绝对路径。列表分组 MUST 当前域组在前、其余按域身份排序，组内按创建时间升序。已取消条目 MUST 照常显示并以弱化样式（变暗加删除线）标识，已完成条目徽章随行变暗；多行内容 MUST 按多行格式渲染。当前域无条目时 MUST 输出空态提示，不静默。

#### Scenario: 默认折叠与展开

- **WHEN** 当前域及其下级域各有条目，分别以默认参数与 `--full` 执行 `list`
- **THEN** 默认输出中下级域仅有标题行；`--full` 输出中下级域条目表全部展开

#### Scenario: 标题相对化

- **WHEN** 当前域为 `/a/b`，其下级域 `/a/b/c` 有 2 条条目
- **THEN** 列表中当前域标题显示 `b`，下级域标题显示 `/c (2)`，不出现 `/a/b` 全路径

#### Scenario: 根域标签

- **WHEN** 以 `-g` 执行 `list`
- **THEN** 当前域标题显示 `GLOBAL`

#### Scenario: 已取消条目的可见与弱化

- **WHEN** 列表或回显中存在已取消条目
- **THEN** 该条目以 `[-]` 标号正常显示，整行以变暗加删除线弱化；文本定位仍可命中它

### Requirement: JSON 机器契约

`--json` 模式 MUST 向 stdout 输出纯净 JSON（无标题、确认行、回显等任何装饰文本）。条目级动词 MUST 输出条目对象数组（单参数也是单元素数组），顺序同参数序；`clear` MUST 输出被清条目数组；`list` MUST 输出扁平条目数组，默认仅当前域条目，`--full` 时为当前域及全部下级域且顺序与人读视图一致。条目对象 MUST 全量携带 `id` / `domain` / `content` / `status` / `created_at` / `completed_at` 六键，`completed_at` 为空时 MUST 为 `null` 而非缺键。失败路径的退出语义 MUST 与人读模式一致。

#### Scenario: 条目动词输出数组

- **WHEN** 以 `--json` 执行 `finish <id>`
- **THEN** stdout 仅为一个含单元素条目对象的数组，该对象六键齐备

#### Scenario: list 输出范围与 --full 联动

- **WHEN** 当前域及下级域各有条目，分别以默认参数与 `--full` 执行 `list --json`
- **THEN** 默认数组仅含当前域条目；`--full` 数组含下级域条目且顺序与人读一致

#### Scenario: 纯净 stdout

- **WHEN** 以 `--json` 执行任何成功的写动词
- **THEN** stdout 仅含 JSON 文本，确认行、列表回显、标题横幅均不出现

### Requirement: 操作后回显当前域现场

人读模式下，全部写动词（`add` / `finish` / `pend` / `reset` / `drop` / `erase` / `clear`）操作成功后 MUST 在确认行之下追加打印当前域的直属条目列表：回显仅含当前域直属条目、不含下级域标题行，行形态与 `list` 条目行一致。批量操作 MUST 按结果类型分行输出单行汇总（「已〈结果〉 N 条：[ID 列表]」），单数与复数使用同一模板，无结果的类型不打印。回显时当前域无直属条目 MUST 打印与 `list` 空态一致的提示。失败路径（缺内容、无命中、多义、拒绝确认）MUST 维持纯错误输出、不回显。`--json` 模式 MUST NOT 输出回显。

#### Scenario: 状态流转后回显

- **WHEN** 人读模式对当前域条目执行 `finish`
- **THEN** 先输出确认行，其下打印当前域直属条目列表（含该条目的已完成形态）

#### Scenario: 清空后空态回显

- **WHEN** 人读模式执行 `clear` 确认后当前域已无条目
- **THEN** 回显打印空态提示，不静默

#### Scenario: 失败不回显

- **WHEN** 目标动词因多义命中报错中止
- **THEN** 输出仅含错误信息与候选列表，不打印任何列表回显
