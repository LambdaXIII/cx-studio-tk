# Spec Delta

## Purpose

定义字幕格式框架的行为契约：适配器接口的职责划分（语法归适配器、语义归框架）、序列与集合的读写映射、格式约束的声明与统一执行、导出裂变、以及格式扩展方式。框架不认识具体格式，只认识符合契约的适配器。

## ADDED Requirements

### Requirement: 适配器契约——语法归适配器，语义归框架

格式适配器以 `Format` 对象为载体——格式身份（名称）、所识别的文件扩展名、约束声明与双向读/写实现打包于一处，扩展名与约束声明归属 `Format` 而非单个读/写实现。适配器 MUST 只承担语法职责：把一个序列解析为片段、把片段序列化为一个序列（含该格式扩展字段读写与扩展位键的格式前缀约定）。集合与序列的映射、交叠切分、序号重编的编号语义、时间精度换算 MUST 由框架统一裁决；格式约束 MUST 以声明形式交由框架检查与执行，MUST NOT 上溯模型，也不得散落由各适配器各自实现。框架不认识具体格式，只依赖适配器契约。

#### Scenario: 适配器只做语法

- **WHEN** 一个适配器收到「把某文件解析为片段」与「把片段写成序列」的请求
- **THEN** 适配器完成语法转换与扩展字段读写，不涉及集合映射、切分或编号决策

#### Scenario: 约束由框架执行

- **WHEN** 某适配器声明其序列不允许交叠
- **THEN** 对该格式的导出由框架按声明执行交叠检查与裂变，适配器自身不含此逻辑

### Requirement: 导入将序列一对一解读为集合

导入以文件为单位：一个输入文件解析为一个序列，该序列 MUST 被解读为一个集合；多个文件各自解读为各自的集合，框架 MUST NOT 把多个序列合并为一个集合。序列中检出的异常状态（如交叠片段）MUST 被忠实保留进集合，不因异常而拒绝导入或丢弃片段。

#### Scenario: 多文件导入各成集合

- **WHEN** 导入两个独立的字幕文件
- **THEN** 得到两个集合，每个集合的内容与对应文件的序列一致

#### Scenario: 异常序列忠实入集

- **WHEN** 导入的序列中存在交叠片段（违反该格式约定的异常状态）
- **THEN** 交叠片段原样落入集合，导入不失败、不丢片、不改写

### Requirement: 导出按声明约束将集合裂变为序列

导出时，若集合不含交叠（或目标格式允许交叠），一个集合 MUST 产出一个序列；若集合含交叠且目标格式声明不允许交叠，框架 MUST 把交叠片段切分到多个序列，产出多个输出，切分 MUST 保证每个序列内部不交叠且按开始时间排列，且 MUST NOT 丢失任何片段。交叠的判定语义与 `ITimeRange.is_overlapped_with` 一致：端点相触（一区间的终点恰为另一区间的起点）不构成交叠，相邻衔接的片段留在同一序列。

#### Scenario: 无交叠导出为单序列

- **WHEN** 导出一个不含交叠的集合到声明不允许交叠的格式
- **THEN** 产出一个序列（一个输出文件）

#### Scenario: 交叠集合裂变为多序列

- **WHEN** 导出一个含交叠片段的集合到声明不允许交叠的格式
- **THEN** 产出多个序列，每个序列内部片段按开始时间排列且互不交叠，全部片段无丢失

#### Scenario: 允许交叠的格式不裂变

- **WHEN** 导出一个含交叠片段的集合到声明允许交叠的格式
- **THEN** 产出一个序列，交叠状态原样保留

### Requirement: 序号在写出时重编

序号是序列侧的编号，MUST NOT 进入模型。编号的语义由框架负责：每个序列 MUST 从 1 连续递增、按片段时序编号、不沿用来源编号；框架完成分组并按序列交付片段表后，适配器在序列化时按交付顺序写出编号字面。

#### Scenario: 裂变后各自重编

- **WHEN** 一个集合裂变为两个序列写出
- **THEN** 每个序列的编号各自从 1 连续递增，与来源编号无关

### Requirement: 时间精度换算由框架执行

模型时间（毫秒级）与目标格式的时间表示之间的换算 MUST 由框架执行，适配器 MUST 声明其格式的时间精度与表示方式。精度取舍 MUST 保持时间顺序：换算后片段的先后关系 MUST NOT 因取舍而颠倒。

#### Scenario: 精度取舍不颠倒时序

- **WHEN** 毫秒级时间换算到精度更粗的格式（本变更的 SRT/TTML/CSV 均为毫秒级，此场景为面向未来更粗精度格式的前瞻性契约；当前由框架的单调取整逻辑承载）
- **THEN** 换算后各片段的开始时间先后关系与换算前一致

### Requirement: 导出文件的命名与编码

导出写出 MUST 使用 UTF-8 编码（不带 BOM）。产出单个输出文件时 MUST 使用目标路径原名；裂变产出多个文件时 MUST 以目标 stem 加 `.part<k>` 序号后缀（从 1 起）派生命名，目录与扩展名跟随目标路径。写入前 MUST 一次性校验全部目标路径，任一已存在则报错中止且不写出任何文件、不覆盖既有文件。

#### Scenario: 裂变多文件命名

- **WHEN** 目标为 `out.srt` 且集合裂变为两个序列
- **THEN** 产出 `out.part1.srt` 与 `out.part2.srt`

#### Scenario: 目标已存在

- **WHEN** 任一目标输出路径（含派生的 `.part<k>` 路径）已存在
- **THEN** 报错中止，不写出任何文件，不覆盖既有文件

### Requirement: 导入无异常时往返对称

对不含交叠的输入（导入未检出异常），「读入后原样导出回同一格式」MUST 恢复与来源等价的序列——片段的时间、台词、说话人、扩展位内容与时序一致（顺序按开始时间判定，来源的文档排列顺序不作为等价判据；等价以模型可承载的内容为界；来源中超出格式实现范围、未被解析入模型的结构不计入等价）。不对称 MUST 仅出现在交叠裂变的异常路径。

#### Scenario: 干净输入往返无损

- **WHEN** 读入一个不含交叠的 SRT 并原样导出为 SRT
- **THEN** 输出与输入在片段、时间、顺序上等价

### Requirement: 新增格式不动框架与模型

新增一个格式 MUST 仅需：在 `subtitler.common.formats` 内实现适配器契约并声明扩展名与约束、在前台完成注册。框架与模型 MUST NOT 因新增格式而修改。字幕模型与 Loader/Saver 契约及 engine MUST 位于可被其它工具 import 的 `subtitler.common` 层；格式实现与框架 MUST NOT 依赖任何 CLI 组件。

#### Scenario: 扩展格式不改核心

- **WHEN** 新增一个格式适配器实现并在前台注册
- **THEN** 框架与模型代码零改动，转换流程照常工作

#### Scenario: `subtitler.common` 层可被其它工具复用

- **WHEN** 另一个工具 import 字幕模型与格式框架
- **THEN** 不引入对任何 CLI 组件（appenv/context/注册接线）的依赖
